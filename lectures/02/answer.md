## 宿題

- 取り組んだレベル：基礎 
- 変えた設定やデータ：`num_train_epochs` を 20 → 5 に変更（40 ステップ → 10 ステップ）。他の設定はすべて同じ。変えたあとはセッションを再起動して上から実行した。`warmup_steps=6` は変えていないので、学習全体に対する warmup の割合は 6/40 から 6/10 に上がっている。cosine スケジュールも 10 ステップで学習率が 0 まで下がる
- 結果（比較表や数字）：
  | | epochs=20（元の設定） | epochs=5（変更後） |
  |---|---|---|
  | ステップ数 | 40 | 10 |
  | `format_rate` | 1.000 | 1.000 |
  | `content_rate` | 0.905（19/21） | 0.762（16/21） |
  | 最終 loss | 0.014 | 1.576 |
  | 学習時間 | 247 秒 | 65 秒 |
  | 退行 | なし | なし |

  epochs=20 の loss の推移：ステップ 10 = 1.561、20 = 0.085、30 = 0.019、40 = 0.014。epochs=5 の最終 loss（1.576）は、epochs=20 のステップ 10 の値とほぼ同じで、epochs=5 は loss が大きく下がる手前で学習を終えている。
  なお、Colab の表示する `Training Loss` は直前 10 ステップの平均なので、epochs=5 の値は学習開始直後の高い loss を含んでいる。

  学習後に内容が × になった質問：

  | 質問 | 正解 | epochs=20 | epochs=5 |
  |---|---|---|---|
  | 成績はいつ出ますか | true | ×（断定） | ○ |
  | オフィスアワーは事前予約が必要ですか | true | ×（断定） | ○ |
  | PDF 以外でも出せますか | false | ○ | ×（逃げた：`true` で「記載がありません」） |
  | オフィスアワーの曜日と時間を教えてください | false | ○ | ×（answer が「質問: オフィスアワーの曜日と時間を教えてください」と質問の復唱） |
  | 提出した課題へのフィードバックはもらえますか | true | ○ | ×（断定：FAQ の 2 文をつなげた） |
  | 課題の文字数に制限はありますか | true | ○ | ×（`true` は正しいが answer が「FAQ には記載がありません。」で「確認」を含まない） |
  | 参考文献の書き方に指定はありますか | true | ○ | ×（同上） |

  `needs_review` の判断だけを見ると、どちらも 21 問中 19 問が正しく、差はなかった。差が出たのは `answer` の文面で、epochs=20 は FAQ の文と定型文（「この FAQ には記載がありません。運営に確認が必要です。」）を一字一句再現していたのに対し、epochs=5 は定型文が途中で切れる、質問を復唱する、FAQ の 2 文をつなげる、といった揺れがあった。
  セクション 6（知識を問う質問）の分類は、epochs=5 でも epochs=20 と同じだった（最終課題の締切は断定、教員名と次回テーマは needs_review）。

  epochs=5 は 2 回実行した。1 回目は `result.json` を保存し忘れたので、提出の値は 2 回目のもの（`result_epoc5.json`）。1 回目は `content_rate` 0.810、学習時間 56 秒で、× になった質問も一部違った。21 問の評価では、1〜2 問の差は実行ごとの揺れの範囲に入る。
- ファインチューニングが向く場面・向かない場面についての考察：
  - **向く場面：出力の形式や答え方をそろえたいとき。** JSON の形式は 10 ステップ（65 秒）の学習で 21 問すべて守れるようになり、40 ステップでも同じだった。プロンプトで形式を指示しても守れなかった小さなモデルでも、14 件の例を見せるだけで形式は身についた。形式を覚えるのに必要な学習量は少ない
  - **定型文まで安定させるには、もう少し学習が要る。** epochs=5 では JSON の型は守れていても、`answer` の文面が途中で切れたり質問を復唱したりした。決まった文を一字一句出させたいなら、loss が十分下がるまで（今回は 20 ステップ以上）学習する必要がある
  - **向かない場面：知識を足したいとき。** 学習量を 4 倍にしても、FAQ に無い事実（教員名など）は答えられないまま。学習データにない知識は増えない。知識を使わせたいなら、FAQ や資料を検索してプロンプトに渡す方法（RAG）の方が合っている。FAQ の内容が変わったときも、学習し直さずに資料を差し替えるだけで済む
  - **「知らないときは確認を求める」判断は、学習量を増やしても完全にはならない。** epochs=20 でも 5 でも、`needs_review` の判断は 19/21 だった。間違え方は、FAQ と似た語を含む質問に FAQ の答えを流用して断定するもの（20・5 の両方）と、FAQ にある質問に「記載がありません」と逃げるもの（5）だった。学習量を増やすと、間違え方が変わるだけで、なくなりはしなかった。判断の正しさが重要な用途では、FT だけに頼らず、根拠の検索や人の確認と組み合わせる必要がある
